# Fictional preparation lifecycle: freeze before review

**Everything in this walkthrough is fictional.** The candidate, organization, opportunity, evidence, résumé baseline, preparation state, and proposed artifacts are invented. They are not records, IDs, files, packet contents, or output from the private system.

## Scenario

Fictional candidate **Avery Rowan** is reviewing a fictional **Workflow Governance Lead** opportunity at **Harborlight Studio**. Deterministic evaluation has already found supported governance and program-direction evidence, one learnable tooling gap, and no disqualifying requirement.

## 1. Preparation eligibility

The preparation command checks that the opportunity is verified, actionable, and supported by a candidate-specific evaluation. If an essential input is missing, preparation stops rather than inventing a path forward.

## 2. Freeze the preparation basis

The system creates a fictional frozen preparation packet containing references to the verified opportunity, the evaluation result, approved evidence, capability assessments, and the selected résumé baseline.

The point is not to preserve a raw data dump. It is to establish the exact basis against which preparation can be reviewed.

## 3. Create only evidence-bound proposed claims

Provider-neutral or synthetic preparation behavior may propose presentation language, but every proposed claim must point to governed evidence. Deterministic validation rejects unsupported numbers, forbidden interpretations, missing evidence, and ownership conflicts.

## 4. Keep artifacts private and traceable

The fictional package can include a review brief, a synthetic résumé draft, a claim manifest, and a QA report. The private artifacts remain profile-owned and traceable to approved evidence; this public example exposes none of their contents.

## 5. Reach a review state

When required information is incomplete or ambiguous, the package reaches **NEEDS_HUMAN**. When deterministic checks pass, it can reach **REVIEW_READY**. Neither state is submission authority.

## 6. Detect divergence instead of drifting

Suppose the fictional opportunity is updated after preparation: its responsibilities now require direct production-software ownership. The current opportunity state no longer matches the frozen basis.

The system detects packet divergence. The earlier package must not silently remain authoritative; it returns to human reconciliation and review before it can be treated as current.

## What this demonstrates

This lifecycle demonstrates snapshot authority, evidence-bound claims, deterministic validation, private artifact custody, and visible human review. It does not demonstrate live LLM generation, browser automation, employer submission, or production document rendering.
